LESSON 01

Transformer 数据流：先盯住 shape

直觉

语言模型反复做两件事：让 token 互相交换信息，再对每个位置独立变换通道。残差把新信息加回原表示，最终投影为下一个 token 的分数。

Shape

(B,T) 的整数 token 经 embedding 变为 (B,T,D)；attention 和 FFN 保持外部 shape；lm head 得到 (B,T,V)。

公式 / 例子

x₀ = Embedding(ids) + Position
x′ = x + Attention(Norm(x))
x″ = x′ + FFN(Norm(x′))

LESSON 02

Attention：共享什么，保留什么

直觉

Q 是“我在找什么”，K 是“我提供什么索引”，V 是“命中后取走的内容”。MHA/GQA/MQA 改变 KV 头共享程度；线性与稀疏注意力改变历史信息的组织或选择方式。

Shape

标准头形状为 Q:(B,Hq,T,Dh)、K/V:(B,Hkv,T,Dh)。GQA 令多个 Q 头共享一组 KV；MQA 令所有 Q 头共享单组 KV。

公式 / 例子

softmax(QKᵀ / √Dh + causal mask)V。因果 mask 不允许位置 t 读取未来；它不改变张量保存历史的需求。

注意力拓扑切换

选择注意力类型
Q→K₁ V₁ · K₂ V₂ · K₃ V₃→O

MHA：每个 Q 头有独立 K/V 头，表达自由度高，KV cache 最大。

LESSON 03

KV Cache：省投影，不等于 O(1) 解码

直觉

生成新 token 时，历史 K/V 不变，可以缓存以避免重投影。但 full attention 的新 Q 仍需与历史 K 做匹配并聚合 V，所以 decode 计算仍随历史长度线性增长。

Shape

展开 cache 常见 shape 为 (B,Hkv,T,Dh) 的 K 与 V。MLA 可以先存 latent，但当前 reference 实现若在写 cache 前展开，就必须按展开 shape 计。

公式 / 例子

bytes = B × L × T × Hkv × (Dk + Dv) × dtype_bytes。GB 使用 10³，GiB 使用 2¹⁰；二者不能混写。

边界：MiniMind 的 KV cache 只避免历史 K/V 重投影；YaRN 默认关闭，32K 是配置上限，1M 超出配置。

KV / 状态计算器

默认示例：MiniMind，32K，BF16，reference。

结果按 B 个请求、每请求 T 个 token 计算，分别列出组成、公式、GB/GiB、完整性和证据口径；不代表 GPU 实测占用。

理解检查：有 KV cache 是否意味着 full attention decode 为 O(1)？

LESSON 04

MoE：少算专家，不代表少通信

直觉

Router 为每个 token 选择 top-k 专家。专家参数可以分散在设备间，因此 token 激活要 dispatch 到被选专家，再 combine 回原设备。

Shape

输入激活 (B,T,D) 选 top-k 后，在朴素上界里产生 k 份路由项。AllToAll 传的是复制后的激活，不是专家权重。

公式 / 例子

remote bytes = B × T × D × k × activation_bytes × remote-route fraction。Gb/s 是 bit/s，GB/s 是 byte/s，相差 8 倍；有效带宽还要乘利用率。

FP4 专家权重不会自动减少激活通信；只有激活本身量化或改变路由/布局才会影响这部分 bytes。

AllToAll 理论下限

结果仅为单向 dispatch 下限，不包含 combine、协议、拥塞和负载不均。

01 / TEACHING BASELINE

nanoGPT

查看来源

解决什么：用最少代码展示 GPT 闭环：embedding、因果 MHA、MLP、残差和语言模型损失。

规模
配置值 12 层、hidden 768、12 头 × 64。
训练目标
源码事实 target shift 在数据加载阶段；forward 直接对齐 logits 与 targets。
缓存口径
reference 没有 KV cache；每步重跑窗口。

文字数据流

  1. (B,T) token 与绝对位置 embedding 相加为 (B,T,768)。
  2. 12 个 Pre-LN block 依次执行因果 MHA 和 GELU MLP，两次残差保持外部 shape。
  3. final LayerNorm 后进入与 token embedding 权重共享的 lm head；推理只投影最后位置。

Causal MHA

Q/K/V 各为 12 头 × 64，causal mask 禁止读取未来。没有 cache 时每一步都重算窗口，attention 主项为 O(T²)。

Pre-LN 残差

先归一化再进入 attention/MLP，子层输出加回 residual；block 前后都保持 (B,T,768)。

GELU 与权重共享

MLP 为 768→3072→768；输入 embedding 与 lm head tied，减少一份词表矩阵。

训练边界

模型 forward 不执行 label shift；数据加载器负责构造后移一位的 targets。

reference 与理论 cache 边界

源码事实 当前 forward 没有 past_key_values。任何标准 MHA cache 数字都只能标为理论假设，不能写成 nanoGPT 当前占用。

02 / MODERN SMALL MODEL

MiniMind

查看来源

解决什么：以教学规模展示 RMSNorm、RoPE、GQA、SwiGLU 与真实生成 cache。

关键参数
配置值 8 层、8 Q 头 / 4 KV 头、head dim 96。
位置边界
最大位置 32K；YaRN 默认关闭。
缓存口径
源码事实 保存 repeat 前的 4 头 K/V。

文字数据流

  1. (B,T) 经 embedding 得到 (B,T,768)，RoPE 从 past KV 长度继续位置。
  2. 每层 Q 为 8×96，K/V 为 4×96；先把未 repeat 的 K/V 写入 cache，再扩为 8 头参与 attention。
  3. RMSNorm、GQA 和 SwiGLU 组成 8 层主干；生成循环下一步只传新 token。

RMSNorm + RoPE

RMSNorm 只按均方根缩放；RoPE 在 Q/K 上注入相对位置信息。配置支持 32K，但 YaRN 分支并非默认启用。

GQA Cache

8 个 Q 头共享 4 个 KV 头，cache 保存 (B,T,4,96) 的 K 与 V，attention 计算时才 repeat 两倍。

SwiGLU

SiLU(gate) × up 后投影回 hidden，比单路 GELU MLP 多一条可学习门控路径。

Prefill / Decode

cache 避免历史 K/V 重投影，但新 query 仍读取全部历史，因此 full-attention decode 每 token 仍随 T 线性增长。

配置范围与换算

推导 B=1、32K、BF16 reference 为 402,653,184 bytes；1M 超出该配置范围，不作为有效运行示例。

03 / HYBRID ATTENTION

Qwen3.6-27B

查看来源

解决什么：用 48 个 Gated DeltaNet 层压缩长历史状态，用 16 个 Gated GQA 层保留内容寻址，并可融合视觉 token。

层布局
配置值 [linear, linear, linear, full] × 16。
实际宽度
hidden 5120；24 Q / 4 KV；full head dim 256；tie_word_embeddings=false。
状态口径
GQA KV + FP32 recurrent + combined-QKV conv state。

文字数据流

  1. 文本 embedding 与可选视觉 PatchMerger 都输出 hidden 5120，并使用 MRoPE position embeddings。
  2. 64 层按三层 DeltaNet 加一层 full GQA 重复；每层后接 5120→17408→5120 SwiGLU。
  3. DeltaNet 保存固定 recurrent/conv state；full 层保存随 T 增长的 4 头 GQA K/V；最终使用独立 lm head。

Gated DeltaNet

K 16×128、V 48×128，combined QKV 投影为 10240；短卷积混合局部信息，delta rule 把历史更新进 48×128×128 FP32 状态。

Gated GQA

Q 投影同时产生 24×256 的 query 与 output gate；4 个 KV 头提供精确内容寻址，6144 宽输出再投影回 5120。

MRoPE 与视觉

视觉塔 hidden 1152、27 blocks，PatchMerger 输出 5120 后替换文本占位 token；纯文本路径不需要视觉输入。

MTP 边界

配置值 声明一层 MTP；源码事实 当前本地 reference 仅忽略相应权重，没有 MTP forward，图中不画成实线路径。

为什么不能只写“线性注意力无 KV”

48 层 DeltaNet 确实使用固定 recurrent state，但还存在 convolution state；16 层 full GQA 的 KV 随上下文增长。B=1、1M、BF16 reference 已计小计为 65,690,927,104 bytes。

04 / MLA + DSA

GLM-5.2

查看来源

解决什么：用 MLA 低秩投影、DSA top-k 和跨层索引复用控制长上下文计算，并用大规模 MoE 扩展参数容量。

主干
配置值 78 层；前 3 层 Dense，后 75 层 MoE。
Indexer
21 个 full Indexer；57 个 shared 层复用 indices。
缓存双口径
reference 展开 K/V；576 维 latent 仅 optimized/theoretical。

文字数据流

  1. hidden 6144 经 Q LoRA 生成 64×256 query；KV 先压到 512+64，再展开为 64 头 K/V。
  2. 21 个 full Indexer 产生 top-2048，后续 57 个 shared 层在层循环中复用 indices；稀疏 mask 约束 MLA attention。
  3. 前 3 层使用 Dense SwiGLU，后 75 层由 256 routed experts top-8 与 1 shared expert 相加。

MLA

K/V 先经 512 维 latent；Q/K 各有 64 维 RoPE 部分。当前 HF/reference cache update 前已经展开 K/V，因此不能用 576 维当 reference。

DSA

Indexer 用低维 key 与 query 计算 ReLU score，再选择 top-2048 历史位置；这是稀疏计算选择，不自动等于压缩 cache。

IndexShare

full 层计算 top-k，shared 层复用上一结果。源码证明跨层复用，但不能据此宣称“唯一原创”，也不能画成 reference GPU broadcast。

MoE

256 routed experts 取 top-8，另有 1 个 shared expert。参数稀疏不意味着激活通信可以忽略。

reference 与 optimized 显存差异

推导 B=1、1M、BF16：reference 展开路径 5,117,184,000,000 bytes；optimized/theoretical 576 维路径 95,232,000,000 bytes。两者不可混写。

05 / LINEAR + MULTIMODAL MOE

Kimi-K3

查看来源

解决什么：以 KDA 递归状态覆盖多数层，以无 RoPE 的 Gated MLA 保留全局 attention，并组合 AttnRes、LatentMoE 与视觉输入。

层布局
配置值 93 层：69 KDA + 24 MLA。
专家
首层 Dense；其余 92 层 896 experts top-16 + 2 shared。
缓存完整性
MLA 可换算；KDA 外部 state dtype/layout 证据不完整。

文字数据流

  1. 文本和 MoonViT 特征统一为 hidden 7168，进入 93 层混合主干。
  2. 69 层 KDA 用 96×128 recurrent state 和三组 short-conv state；24 层 MLA 使用 Q 96×192、K 96×192、V 96×128。
  3. AttnRes 在层 0、12…84 共 push 8 次；首层 Dense，其余层经 3584 latent 空间路由 896 experts。

KDA

Q/K/V 各先过 kernel=4 ShortConv，再由 delta rule 更新固定 recurrent state；存在状态不等于已经获得精确 byte 证据。

Gated MLA

rotary_emb=None，不执行 RoPE。reference 保存展开 K/V；optimized 仍需 512 latent 加参与 key 的 64 remainder，共 576 维。

AttnRes

每 12 层维护 block residual，通过归一化、打分和 softmax 加权汇合；触发包含 layer 0，因此是 8 次而非 7 次。

LatentMoE

router 在 7168 hidden 上选 top-16，routed 路径先降到 3584 再进入专家，最后升回 7168 与 shared experts 相加。

视觉与 MTP

MoonViT-V2 投影到 7168；num_nextn_predict_layers=0，不能在结构图里画内置 MTP。

为什么 KDA 不能写成精确 217MB

本地源码能证明 recurrent 与 q/k/v convolution state 存在，但外部 FLA state 的完整 dtype/layout 证据不足。因此 1M reference 与 optimized 数值都只显示 MLA 已计小计，并明确 KDA 未计项。

06 / COMPRESSED SPARSE ATTENTION

DeepSeek-V4-Flash-0731

查看来源

解决什么：以 MQA、滑窗和压缩稀疏历史控制 1M 上下文成本，再用 mHC、MoE 与版本化 DSpark 组合推理。

主干分布
配置值 43 层：ratio 0/4/128 分别 2/21/20。
注意力
64 Q heads × 512；单 512 维 MQA KV projection。
版本边界
HF next-n=1、inference MTP=3、vLLM 7 tokens 分属不同入口。

文字数据流

  1. hidden 4096 展开为 4 份，43 个 block 分别在 attention 与 FFN 前后由 mHC 混合残差。
  2. Q 为 64×512，KV 为单 512 投影；2 层只看 window 128，21 层 ratio=4 配 Indexer，20 层 ratio=128 使用压缩历史。
  3. MoE 选择 256 routed experts 中 top-6 并加 1 shared expert；DSpark 作为独立版本路径注入主干后段。

CSA / HCA

ratio=4 使用 overlap compressor 与 top-512 Indexer；ratio=128 使用 non-overlap 压缩位置。稀疏计算、预分配 cache 与部署量化是三个不同问题。

MQA

64 个 query heads 共享单个 512 维 K/V projection，RoPE 只作用于最后 64 维；reference 仍按实际预分配 buffer 计量。

mHC

hc_pre 的 4×4 mixing matrix 做 20 次 Sinkhorn；hc_post 把新输出与四份 residual 混合。最终 hc_head 使用 sigmoid，不是 Sinkhorn。

MoE 与 FP4

sqrtsoftplus router 选 top-6。FP4 描述专家权重格式，不会自动把 BF16/FP8 activation 通信减半。

DSpark

inference 快照为 3 blocks、block_size=5、注入层 40–42；官方 vLLM 的 7 speculative tokens 是部署参数，不能合并成同一个数字。

reference 与 deployment 小计

推导 B=1、1M reference 为 6,897,831,936 bytes，attention core、FP32 Compressor state 与 Indexer cache 单列；mixed deployment raw subtotal 为 3,119,019,008 bytes，后者未计 scale、metadata、packing/alignment，不能称完整总量。

01 / RUNTIME BOUNDARIES

总体集群与并行边界

模型计算图只决定可切分的张量；TP collective、EP dispatch/combine、Prefill/Decode 池和网络拓扑属于运行时。图中不固定 GPU 型号、带宽或微秒延迟。

读取方法

  1. 先确定模型实际产生哪些 KV、recurrent、convolution 或 compressor state。
  2. 再选择 TP/EP/PD 拓扑；模型配置本身不能推出 collective、有效带宽或端到端延迟。
  3. 任何时间估计都必须给出 bytes、单位、效率和未计开销。
02 / GLM DEPLOYMENT VIEW

GLM-5.2 · MLA / IndexShare / MoE

HF/reference 没有实现这里的分布式 EP。full Indexer 产生的 topk_indices 是层间张量复用，不是源码中的 GPU broadcast；EP 只作为带公式的部署假设。

通信口径

部署假设 单向远端 routed payload 下限为 B × S × 6144 × 8 × activation_bytes × remote_fraction。dispatch 与 combine 应分列，不能漏掉 top-k 或远端比例。

03 / KIMI DEPLOYMENT VIEW

Kimi-K3 · 混合注意力与 LatentMoE

当前 reference 为 ep_size=1。只有 runtime 确实在 down projection 后 dispatch，网络 payload 才能用 3584 latent 维；这是一项条件明确的部署选择。

通信口径

部署假设 若 down projection 后 dispatch，单向 payload 下限为 B × S × 3584 × 16 × activation_bytes × remote_fraction。KDA state 精确 bytes 仍为未知，不能恢复旧版 217MB 定值。

04 / DEEPSEEK REFERENCE COLLECTIVES

DeepSeek-V4 · TP、Indexer 与专家分片

这一图优先画官方 inference reference 的实际 collective：Indexer score 和 rank-local expert output 都执行 dist.all_reduce。AllToAll EP 只作为其他 runtime 可能采用的虚线替代。

关键纠错

  1. MQA KV 使用非并行 Linear，reference rank 上重复计算/保存；不能简单写成“KV 无通信所以免费”。
  2. Indexer local scores 需 all-reduce 后形成 global top-k。
  3. FP4 专家权重格式不会自动减少 activation collective。
05 / QWEN TP PLAN

Qwen3.6 · 混合层状态与 TP

Transformers TP plan 混合 colwise、rowwise 与 gather output；旧版固定“每 GPU 24 recurrent heads、out_proj 后一次 AllReduce”没有足够证据，因此改为 projection 级边界。

状态口径
